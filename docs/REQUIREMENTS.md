## Ambiguities and unresolved questions

- **A-001 — `conversation_id` creation contract (resolved for prototype):** `/upload` requires a caller-provided ID, reuses it when present, and creates that ID when new (DEC-011).
- **A-002 — “last 5 messages” (resolved for prototype):** use the five latest individual role messages in chronological order; the current question is separate (DEC-019).
- **A-003 — `/chat` JSON schema and citation shape (resolved for prototype):** return conversation ID, status, answer with numbered markers, and structured document-ID/filename/one-based-page citations (DEC-019, DEC-042).
- **A-004 — document scope (resolved for prototype):** uploaded documents are scoped by conversation (DEC-011); Stage 3 must enforce the metadata filter during retrieval.
- **A-005 — indexing completion semantics (resolved for prototype):** upload is synchronous and confirms success only after vector-count verification and relational finalization (DEC-012).
- **A-006 — source precedence/conflict behavior (resolved for prototype):** authority may be established by explicit supersession/replacement, a later effective version with the same policy ID and scope, or an explicit interim/temporary-to-comprehensive lifecycle. Dates alone never establish precedence. Compatible scopes are combined, true unresolved conflicts are disclosed, and silence is not converted into permission or prohibition (DEC-019, DEC-039). Enterprise governance remains Stage 6.
- **A-007 — citation granularity (resolved for prototype):** return numbered inline markers plus structured document ID, PDF filename and one-based page citations; the web client opens the retained PDF at that page (DEC-019, DEC-042).
- **A-008 — model/network expectations (resolved for prototype):** embeddings run locally; chat uses hosted Gemini Flash with an environment-only key. Sample/fixture transfer is approved for these live checks; enterprise data approval remains separate. Selected cost/latency measurements are recorded, not production targets. Provider tier/data terms require organizational review (DEC-020/069).
- **A-009 — non-functional thresholds:** “Robust,” latency, quality, scalability, security, and availability have no numeric targets. Prototype targets and enterprise SLOs must be proposed and labeled as assumptions.
- **A-010 — cloud context:** A cloud-native choice is encouraged, but preferred provider, existing Apex contracts, region/data residency, security controls, and budget are unknown.
- **A-011 — deliverable medium:** Repository/ZIP and presentations are required, but due date, slide template, presentation length, and submission mechanism are not supplied.
- **A-012 — PDF support boundary (resolved for prototype):** text-readable PDFs up to 10 MiB are supported; encrypted, malformed, and text-empty PDFs are rejected; OCR and multilingual guarantees are excluded.
